# 요구사항을 관찰 가능한 약속으로 바꾸기
“안전하게 코드를 수정한다”만 쓰면 AI는 확인창 하나로 끝낼 수도 있습니다.

다음은 하나의 예이며 그대로 선택할 필요는 없습니다.

- 대상은 내가 선택한 실습 폴더의 텍스트 파일이다.
- 프로그램은 적용 전 파일 경로와 변경 전후를 보여 준다.
- 승인은 표시한 변경 한 건에만 유효하다. 내용이 달라지면 다시 표시한다.
- 거절하면 파일은 그대로이고, 작업에는 거절 이유가 남는다.
- 적용 후에는 지정한 테스트만 실행하고 종료 코드와 출력을 보여 준다.

이에 대응하는 검증은 “거절 버튼이 있다”가 아니라 “거절 전후 파일 내용이 같다”입니다. 인터페이스에는 어떤 작업·변경에 대한 승인인지 식별하는 입력이 필요합니다. 하나의 요구가 화면, 계약, 구현, 검증으로 이어지는 것을 확인하세요.

반대로 “Python FastAPI로 특정 함수 20개를 만들어라”는 사용자 문제보다 구현을 먼저 고정한 명세일 수 있습니다. 팀에 정해진 기술 제약이 있다면 이유를 적고 사용할 수 있지만, 이 실습에서는 학생이 선택합니다.
